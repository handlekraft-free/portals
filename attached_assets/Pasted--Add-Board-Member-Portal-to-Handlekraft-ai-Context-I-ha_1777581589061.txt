# Add Board Member Portal to Handlekraft.ai

## Context
I have an existing nonprofit website at www.handlekraft.ai with three user 
profiles already implemented: Team Member (employee), Student, and Client. 
I need you to add a fourth user profile — Board Member — and build out a 
board portal with the features described below.

Please first examine the existing codebase to understand:
- How the current three user profiles are implemented (auth, roles, 
  permissions, routing)
- The existing UI patterns, component library, and styling conventions
- The database schema and ORM in use
- How file uploads and document storage currently work (if at all)

Match the existing patterns rather than introducing new ones. Ask me 
clarifying questions before making major architectural decisions.

## Legal Context (Important)
This is a California nonprofit public benefit corporation. The portal must 
be designed with California Corporations Code compliance in mind. 
Specifically:
- Board actions can only be taken at duly-held meetings or by unanimous 
  written consent (Cal. Corp. Code § 5211(b))
- There is NO majority email/async voting — do not build a generic voting 
  tool
- Every director has an absolute right to inspect all corporate records 
  (Cal. Corp. Code § 6334) — design accordingly
- Meeting minutes must be retained permanently
- Proper meeting notice must be tracked

## New User Profile: Board Member

Add Board Member as a fourth user role with these properties:
- Standard auth fields (matching existing user profiles)
- Term start date and term end date
- Board position (e.g., Chair, Vice Chair, Secretary, Treasurer, Director)
- Committee assignments (multi-select; committees are configurable)
- Bio and photo
- Emergency contact (optional)
- Indicator for whether they are an "interested director" for any current 
  matter (used for conflict-of-interest tracking)

Board Members should have access to the Board Portal (described below) 
plus read access to anything Team Members can see that's relevant. They 
should NOT see Student or Client data unless explicitly granted.

Add an admin interface for managing board roster, terms, and committee 
assignments.

## Board Portal Features

Build a unified Board Portal section accessible only to Board Member role 
(and admins). Include the following modules:

### 1. Board Dashboard (landing page)
- Next meeting date with RSVP status
- Action items assigned to the logged-in member with due dates
- Recently posted documents
- Outstanding items needing attention (unsigned COI disclosure, 
  unacknowledged policies, pending action items)

### 2. Board Calendar & Meetings
- Calendar view of board meetings, committee meetings, and key deadlines
- RSVP tracking for each meeting (Yes / No / Tentative)
- Quorum indicator based on RSVPs
- Meeting notice tracking: when notice was sent, to whom, by what method, 
  and timestamp of any waivers (directors can waive notice)
- Attendance tracking after each meeting (synced with minutes)
- Method of participation field per attendee (in-person vs. remote)

### 3. Meeting Packet Assembler
- For each upcoming meeting: agenda + linked supporting documents
- Generate a single downloadable PDF of the full packet before the meeting
- Optional: distribute packet via email to all members on a schedule

### 4. Meeting Minutes
Template-based minutes creator with these required structured fields:
- Meeting type, date, time, location (or "remote via [platform]")
- Attendees with method of participation (in-person/remote)
- Absent directors (notice given/waived)
- Quorum confirmation
- For each motion / action taken (this replaces a voting tool):
  - Motion text
  - Mover and seconder
  - Vote count: for / against / abstain
  - Names of any recused directors and the reason for recusal
  - Whether motion passed
- Reports given (executive director, treasurer, committees) with summary
- Action items with owner and due date
- Adjournment time
- Approval status (draft / pending approval / approved at [date])

Minutes must be permanently retained. Include version history. Approved 
minutes should be locked from editing.

Show guidance text to the drafter noting that all directors have 
inspection rights, so sensitive discussions should be paraphrased rather 
than attributed to specific individuals.

### 5. Document Management
- Folders/categories: Bylaws & Policies, Financials, Meeting Materials, 
  Strategic Plan, Legal, Personnel (restricted), Written Consents, 
  Past Resolutions Archive
- Version control on all documents (especially bylaws/policies)
- Acknowledgment tracking: ability to require board members to confirm 
  they've read a document, with timestamps
- Document retention policy field per category
- Audit log of who viewed/downloaded each document
- Search across all documents
- Confidentiality markings (Public / Board-Only / Restricted)

### 6. Written Consents (in lieu of meetings)
A simple workflow for the rare case of unanimous written consent:
- Upload a draft resolution
- Send to all directors for signature/consent
- Track each director's affirmative consent (must be unanimous to be valid)
- If any director does not consent, mark as failed and require a meeting
- Store completed consents in the document repository under "Written 
  Consents"
- Auto-flag interested directors who should be excluded from the 
  unanimity count

### 7. Conflict of Interest Disclosures
- Annual disclosure form (auto-prompt each fiscal year)
- Per-meeting disclosure capability tied to specific agenda items
- Track recusals from votes (feeds into minutes)
- Admin view of all current and historical disclosures

### 8. Board Directory
- All current board members with photos, bios, contact info
- Term start/end dates and which seats are up for renewal
- Committee assignments
- Past board members archive

### 9. Discussion Forums
- Topic-based forums for informal discussion between meetings
- Clear banner on every forum page: "Forum discussions are informal and 
  do NOT constitute official board action. Board action requires a duly-
  held meeting or unanimous written consent."
- Forum posts retained per the document retention policy
- Optional: per-committee private forums

### 10. Budget & Financials Viewer
- Display current budget and financial reports
- Read-only view in browser (do not allow editing of source files)
- Allow Excel/PDF download for offline review
- Versioned: each monthly/quarterly update is a new version, prior 
  versions accessible
- Clear "as of" date on every report

### 11. Action Item Tracker
- Items created during meetings carry forward
- Owner, due date, status (open / in progress / complete)
- Visible on dashboard and reviewable in next meeting's minutes prep

### 12. Onboarding Hub (for new board members)
- Required reading list (bylaws, COI policy, strategic plan, recent 
  minutes)
- Acknowledgment tracking for required readings
- Orientation materials and FAQs
- Mentor pairing field (optional)

### 13. Notification Preferences
- Per-user settings for email vs. in-app notifications
- Categories: meeting notices, document uploads, action items, forum 
  activity, COI prompts

## Cross-Cutting Requirements

- All board portal data is sensitive; ensure proper access controls
- Audit logging on all document access and significant actions
- Mobile-responsive (board members will check this on phones)
- Email notifications for: meeting notices, RSVPs needed, action items 
  assigned, documents requiring acknowledgment, COI disclosure prompts
- Search across documents, minutes, and resolutions
- Export capability for compliance/audit purposes

## What NOT to Build
- Do not build a general async/email voting tool — California law does 
  not permit majority email votes for nonprofit boards
- Do not allow editing of approved minutes (locked records)
- Do not allow board members to edit budget source files (read-only)

## Deliverables
1. Database schema additions/migrations
2. Board Member user profile and role-based access control
3. All thirteen portal modules above
4. Admin interface for managing the board roster and portal configuration
5. Updated navigation reflecting the new role
6. Brief documentation for me on how to administer the portal
