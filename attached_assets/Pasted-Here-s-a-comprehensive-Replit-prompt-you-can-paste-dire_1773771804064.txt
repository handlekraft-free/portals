## Security Requirements

- All routes protected by auth middleware — unauthenticated = redirect to login
- Role-based access control on every endpoint:
  - Clients can only read/write their own data
  - Students can only read their enrolled content
  - Employees can access employee tools + client data (not admin)
  - Admin can access everything
- Passwords hashed with bcrypt (salt rounds: 12)
- JWT secret stored in environment variable `JWT_SECRET`
- File uploads: validate MIME type, limit size, store outside web root, serve via authenticated endpoint
- SQL injection prevention via parameterized queries only
- XSS prevention: sanitize all user input
- CSRF protection on state-changing endpoints

## Critical Implementation Notes

1. **Public site preservation:** Read the existing public site files first. Identify the navigation component. Add ONLY a Login button. Do not change colors, fonts, layout, or content.

2. **Database migrations:** Run schema.sql then seed.sql automatically on first start if tables don't exist. Use a `migrations` table to track this.

3. **Kanban drag and drop:** Cards must persist their new position immediately on drop via API call. Use optimistic UI updates.

4. **Timer persistence:** The running timer should survive page refresh. Store start_time in the database when timer starts, not just in memory.

5. **File serving:** Never expose file system paths in URLs. Use file IDs: `/api/files/:id/download` — verify ownership before serving.

6. **QuickBooks IIF format:** IIF files must use the correct headers: `!TRNS`, `!SPL`, `!ENDTRNS` with proper field mapping. Test with a sample export.

7. **Responsive design:** All three portals must work on tablet and mobile. Kanban board scrolls horizontally on small screens.

8. **Error handling:** All API routes return consistent JSON: `{ success: bool, data: any, error: string }`. Frontend shows user-friendly error messages.

9. **Loading states:** Every data fetch shows a skeleton loader or spinner. No blank screens.

10. **Timestamps:** Store all times in UTC. Display in user's local timezone.

A few things worth knowing before you run this:

**On the public site preservation** — Replit Agent will try to read your existing files before touching them, but I'd strongly recommend making a manual backup/snapshot of your current public site files first, just in case. The prompt tells it explicitly not to modify content, only to add the login button.

**On QuickBooks integration** — the prompt specifies IIF file export (the older universal QB import format) plus CSV. This works with QuickBooks Desktop and Online. If you later want a live API sync with QuickBooks Online via OAuth, that's a separate phase — this gets you clean, importable files immediately.

**On the database** — the prompt uses Replit's built-in PostgreSQL. When you create the Repl, make sure to enable the PostgreSQL integration so `DATABASE_URL` is automatically available as a secret.

**Recommended approach:** Paste this into a **new Replit Agent** conversation (not your existing public site Repl). Once the portal is built and tested, you can either point your domain's subdomain (e.g. `app.handlekraft.ai`) to the new Repl, or have Replit Agent carefully merge the portal into your existing Repl as a second step. Merging second is safer than building directly in your live public site.
